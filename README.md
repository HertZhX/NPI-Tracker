# NPI Tracker 新品导入阶段门管理

面向新品导入的局域网协同工具。支持多个独立项目，并按产品实际适用的 **P、EB、PP、MP** 阶段门跟进关键任务、标准输出文件、资料/工装与 BOM 材料准备情况。系统使用服务端账号登录和 SQLite 持久化，不依赖前端“切换账号”模拟权限。

## 功能范围

- 项目采用“项目代码 → 多个产品”两级结构；同一大项目可包含多个产品，并以“产品料号 + 产品名称”共同区分和检索。
- 产品版本以文本方式手动填写和更新，不需要上传版本文件。
- 产品文件和阶段交付文件可分别维护文件版本；更新版本不要求重新上传附件。
- 每个产品按 **P → EB → PP → MP** 顺序推进，并可在任一阶段结束产品流程；新建时选择终止阶段，系统自动生成连续阶段链，历史跳阶段配置也会安全迁移为连续链。
- 管理员可提前完结尚未完成全部阶段的项目，未完成事项和历史数据继续保留；需要继续推进时可恢复为进行中。
- P、EB、PP 的阶段门只检查当前阶段必需关键任务，MP 阶段额外检查产品全部必需交付文件；停用事项采用软删除，历史记录与附件保留并可恢复。
- 每个阶段均包含阶段前启动会和阶段后评审会，可维护时间、参会人、结论及会议附件；只有会议和阶段内容满足条件后才允许流转。
- 管理员可在产品当前阶段新增、修改或停用关键任务和交付文件，也可独立修改项目显示名称、产品名称、料号和版本。
- 项目总览集中展示全部项目、产品及 P/EB/PP/MP 阶段整体进度，并可直接进入对应产品流程。
- 文件跟踪提供当前产品的全阶段资料/工装收集总表，同时保留各阶段物料资料明细矩阵。
- 阶段总览包含连续阶段、前后会议、关键任务、MP 全交付文件门禁、材料齐套与附件证据。
- 资料/工装进度矩阵，包含 PFMEA（兼容 Excel 中的 `PFM`）、BOM、图纸、检具、治具等交付项。
- BOM 导入后按料号逐项确认准备状态，并支持将当前阶段或所选材料一键全部标记为准备完成。
- BOM 重复导入会保留有效责任与确认信息；历史失效账号会自动解除绑定，需要时回退为待确认，避免阻塞整批导入。
- 报价单支持整张 `.xlsx`/`.csv` 导入，自动识别料号、单价、币种和供应商列，并按 BOM 料号或厂内料号批量匹配；原始文件只保存一份，匹配价格逐项关联到 BOM，支持下载、历史查看与删除。
- 桌面端左侧导航可手动收起或展开，并在当前浏览器中记住选择。
- 责任人分配、状态、日期、阻塞原因、备注和附件信息跟进。
- 管理看板、状态筛选、Excel 导入/导出、BOM 重复导入保护。
- 服务端登录会话、接口权限校验、对象级数据隔离和操作审计。

## 权限说明

系统角色与岗位分开管理；“采购、工程、品质”等是岗位，“管理员、成员”决定系统权限。

| 能力 | 管理员 | 成员 |
| --- | --- | --- |
| 查看项目数据 | 全部 | 本人负责的产品，以及与本人事项/任务/BOM 相关的产品阶段门总览 |
| 新建/删除项目、编辑项目/产品名称、阶段流转、配置模板、导入 Excel/BOM | 可以 | 不可以 |
| 分配阶段事项、资料任务和 BOM 物料责任人 | 可以 | 不可以 |
| 更新阶段事项 | 全部事项 | 仅本人事项的进度、预计日期、阻塞、备注和附件信息 |
| 更新资料任务 | 全部任务 | 仅本人任务的进度、预计日期、阻塞、备注和附件信息 |
| 更新 BOM 物料 | 全部物料 | 仅本人负责物料的准备状态、问题和 ETA |
| 上传/下载报价单 | 全部 BOM 物料 | 仅本人负责的 BOM 物料 |
| 删除报价单 | 全部报价单 | 仅本人上传的报价单 |
| 创建、停用、重置账号及调整系统角色 | 可以 | 不可以 |
| 修改本人密码、退出登录 | 可以 | 可以 |

删除项目是不可恢复操作。系统会同时清理该项目的阶段、物料、任务、BOM 明细、BOM 导入记录和报价单文件，但会保留全局交付模板、账号与审计日志；操作前请先完成必要备份。删除阶段同样不可恢复，并会清理该阶段的任务、交付文件、物料、BOM、报价单、导入记录和附件；系统要求管理员输入阶段代码二次确认。

权限由服务端按当前登录会话再次检查。修改浏览器页面或直接调用接口，都不能越权读取或提交其他责任人的材料。

## 启动

需要 Node.js 22 以上版本，已在 Node.js 24 验证。

### 开发运行

```powershell
npm install
npm run dev
```

开发模式会同时启动前端和 API，浏览器打开命令行显示的地址（通常为 `http://localhost:4173`）。

### 构建后运行

```powershell
npm install
npm run build
npm start
```

默认监听 `127.0.0.1:4173`。需要从局域网访问时，可在启动前设置监听地址：

```powershell
$env:HOST = "0.0.0.0"
$env:PORT = "4173"
npm start
```

### Windows Server 便携包

在 Windows x64 开发机执行：

```powershell
npm run package:windows
```

命令会先执行生产构建，再在 `release` 目录生成包含 Node.js 运行时的便携文件夹、ZIP 压缩包和 SHA-256 校验文件。服务器不需要安装 Node 或 npm；解压后双击 `start-npi.cmd` 即可运行。详细配置、备份及 IIS HTTPS 反向代理说明见压缩包内的 `README-Windows-Deployment.txt`。

## 首次管理员登录

数据库第一次创建时，系统会初始化管理员账号 `admin`，初始密码为 `admin123`。该密码只用于首次登录；登录后系统会强制设置至少 8 位的新密码，不限制字符组合，在完成修改前不能进入业务页面。

也可以在第一次启动前指定临时密码；密码至少 8 位：

```powershell
$env:NPI_BOOTSTRAP_PASSWORD = "Npi12345"
npm start
```

如果数据库已经初始化，再设置该变量不会覆盖现有密码。遗失管理员密码，或第一次启动中断而没有记下临时密码时，不要删除数据库；可先停止服务，再执行：

```powershell
npm run admin:reset
```

命令默认会为 `admin`（兼容旧版 `zhangmin`）生成只显示一次的临时密码，并要求下次登录立即改密。需要恢复其他管理员时，可先设置 `$env:NPI_ADMIN_USERNAME = "账号"`。已有另一名管理员可登录时，也可以直接在账号管理中重置。

## 创建和分配成员

1. 管理员登录后打开账号管理，创建成员账号并填写姓名、部门和岗位。
2. 系统生成一次性临时密码；请当面或通过公司认可的安全渠道交给成员。
3. 成员使用自己的账号登录，并在首次登录时修改密码。
4. 管理员可在新建项目时把成员设为产品负责人，也可在阶段事项、进度任务或材料清单中把责任人分配到该账号。
5. 成员登录后会看到本人负责或有本人工作项的产品；产品负责人可查看对应产品阶段总览，但仍只能提交明确分配给自己的事项、任务和 BOM 物料。

管理员重置密码后，旧登录会话会失效，系统会生成新的临时密码并要求成员再次修改。停用账号或调整角色也会使该账号已有会话失效。未被项目、任务、BOM、确认或责任提交历史引用的账号可以永久删除；已有记录的账号只能停用。建议至少保留两个管理员账号，避免唯一管理员不可用。

## 数据与备份

- 默认数据库：`server-data/npi-tracker.sqlite`。
- 可在启动前通过 `NPI_DB_PATH` 指定其他 SQLite 文件路径。
- 数据库使用 WAL 模式，运行期间还可能存在 `-wal`、`-shm` 文件。
- 最稳妥的备份方式是先停止服务，再复制整个 `server-data` 目录；恢复时同样先停止服务，然后替换为完整备份。
- 备份中包含账号、密码哈希、业务数据、报价单原始文件、会话和审计记录，应按公司敏感数据管理要求加密并限制访问。

## 局域网安全部署

正式多人使用时，建议通过 Nginx、IIS 等反向代理提供 HTTPS，只开放 HTTPS 入口，不要把应用端口直接暴露到公网。确认外部访问已经是 HTTPS 后启用 Secure Cookie：

```powershell
$env:HOST = "127.0.0.1"
$env:NPI_COOKIE_SECURE = "1"
npm start
```

反向代理需把请求转发到应用的同一站点地址。请同时限制数据库目录的系统访问权限、定期离线备份，并为每个人创建独立账号，不要共用管理员账号。

## Excel 与 BOM 导入

- 推进表优先读取“产品”工作表，前 8 列作为物料基础信息，第 9 列起作为交付项。
- `PFM` 会统一为 `PFMEA`，`波封焊载具` 会统一为 `波峰焊载具`。
- BOM 会识别 `CODE/物料编码`、`NAME/物料名称`、`SPEC`、`Quantity/QTY`、位号、供应商和 MPN；`NC`、`DNP`、`DNI`、`NOT FITTED` 行会被排除。
- 表内项目型号与当前项目不一致时会阻止导入，避免跨项目误写。

## 当前限制

- Excel、BOM 和整表报价单由登录用户的浏览器解析，再把结构化结果提交给服务端；服务端会再次校验料号、BOM 关联、责任权限、单价和文件内容。
- 阶段任务、交付文件和阶段会议中的新附件会保存真实文件内容，登录后可在线预览图片、PDF、TXT、CSV 和 XLSX，并可下载 Word、PowerPoint、旧版 Excel 等文件；每个事项最多 20 个附件，单次新增总量上限为 10 MB。升级前仅保存名称和大小的历史附件没有原始内容，需要重新上传后才能预览。材料准备中的整表报价单上限为 10 MB，支持 `.xlsx` 和 `.csv`。
- 旧版保存在浏览器 `localStorage` 的数据不会自动迁移，也不会被本版自动删除。升级前可先在旧版导出 Excel，再由管理员在本版导入；完整的自动迁移工具尚未提供。
- 当前采用单机 SQLite，适合单公司局域网的首版协作。并发量、项目数量或附件存储需求明显增加时，建议升级为集中式数据库和文件存储。
